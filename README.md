# car_s

ROS 2 (Jazzy) software for a Raspberry Pi 4 robot car with four stepper motors,
an RPLIDAR A1, an MPU6050 IMU (accelerometer + gyro) and a QMC5883L magnetometer.

The Pi runs the hardware nodes. The car is normally driven from another Linux
machine running ROS 2 on the same network, using `key_cmd`.

## Hardware

| Part | Details |
|---|---|
| Computer | Raspberry Pi 4 Model B, Ubuntu 24.04, ROS 2 Jazzy |
| Motors | 4 steppers, 200 steps/rev, step/dir drivers with M0/M1/M2 microstep pins (up to 1/32) |
| Wheels | 0.21 m travel per revolution, 0.2337 m between left and right wheels |
| Lidar | RPLIDAR A1 on USB, `/dev/ttyUSB0`, 115200 baud |
| IMU | MPU6050 on I2C bus 1, address `0x68` |
| Magnetometer | QMC5883L on I2C bus 1, address `0x0D` |
| LEDs | Red on GPIO 23, blue on GPIO 24 (blue flashes while the motors are enabled) |

Step pulses are generated by the Pi's hardware PWM, so the two motors on each
side share one PWM channel: left on PWM1 (GPIO 13 and 19), right on PWM0
(GPIO 18 and 12). For that reason onboard audio must be disabled (it uses the
same PWM hardware), and nothing else may use GPIO 12, 13, 18 or 19.

The magnetometer shares the IMU's I2C bus (SDA/SCL).

## Nodes and topics

| Executable | Runs on | What it does |
|---|---|---|
| `car_s_controller_accel` | Pi | Drives the steppers from `cmd_vel` with an acceleration ramp, publishes odometry |
| `car_imu` | Pi | Reads the MPU6050 at 200 Hz, publishes `imu/data_raw` |
| `car_mag` | Pi | Reads the QMC5883L at 10 Hz, publishes `imu/mag` |
| `key_cmd` | Remote PC | Keyboard teleop |
| `imu_normalize` | Either | Prints running averages of `imu/data_raw`, for calibration |

The controller ramps each wheel's speed towards its target at `motor_accel`
m/s² (default 1.0) rather than jumping straight to it, so the steppers don't
slip or stall when a high speed is commanded.

### Controller topics

Subscribed:

| Topic | Type | Meaning |
|---|---|---|
| `cmd_vel` | `geometry_msgs/Twist` | `linear.x` in m/s, `angular.z` in rad/s (positive = anticlockwise) |
| `motor_on` | `std_msgs/Bool` | Enables or disables the stepper drivers. **The motors stay disabled until this is set true.** |
| `motor_mode` | `std_msgs/Int32` | 1 = continuous (keep going until told otherwise), 2 = auto (stop 0.1 s after the last `cmd_vel`, the default), 3 = turn 360 (stop after one full spin) |
| `motor_steps` | `std_msgs/Int32` | Microsteps: 1, 2, 4, 8, 16 or 32 (default 32) |
| `motor_accel` | `std_msgs/Float32` | Acceleration ramp in m/s², 0 = no ramp |

Published: `odom` (`nav_msgs/Odometry`), TF `odom` → `base_link`,
`left_speed` and `right_speed` (m/s), `angle` (heading in degrees).

Odometry is worked out from the step pulses sent to the motors, so it is wrong
if the wheels slip.

### Frames

`odom` → `base_link` comes from the controller. `robot_state_publisher` adds
`base_link` → `imu_link`, `laser_link` and the wheel links from
[urdf/robot_car.urdf.xml](urdf/robot_car.urdf.xml).

## Setting up the Pi from scratch

### 1. Operating system

Install Ubuntu 24.04 for Raspberry Pi, then set these in
`/boot/firmware/config.txt` and reboot:

```
dtparam=audio=off
dtparam=i2c_arm=on
```

Audio must be off because it uses the PWM hardware that drives the motors.

Add your user to the `dialout` group so the lidar serial port can be opened
without `sudo` (log out and back in afterwards):

```bash
sudo usermod -aG dialout $USER
```

### 2. ROS 2 Jazzy

Follow the [ROS 2 Jazzy Ubuntu install guide](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html),
installing `ros-jazzy-ros-base` (no desktop is needed on the Pi), then the
build tools:

```bash
sudo apt install python3-colcon-common-extensions python3-rosdep
sudo rosdep init
rosdep update
```

### 3. pigpio

All hardware nodes talk to the `pigpiod` daemon. Ubuntu doesn't package it, so
build it from source:

```bash
mkdir -p ~/src && cd ~/src
wget https://github.com/joan2937/pigpio/archive/master.zip
unzip master.zip
cd pigpio-master
make
sudo make install
sudo ldconfig
```

The C library and daemon are what matter; if the Python part of
`make install` fails it can be ignored.

Then run `pigpiod` as a service so it starts at boot. Create
`/etc/systemd/system/pigpiod.service`:

```ini
[Unit]
Description=Pigpio daemon
After=network.target

[Service]
Type=forking
PIDFile=/run/pigpio.pid
# -n: only accept connections from localhost
ExecStart=/usr/local/bin/pigpiod -n 127.0.0.1
ExecStop=/bin/systemctl kill pigpiod

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pigpiod
pigs hwver        # prints a number if pigpiod is working
```

Without `-n 127.0.0.1`, anyone on the network could control the GPIO pins.

### 4. Workspace

```bash
mkdir -p ~/ros_ws/src && cd ~/ros_ws/src
git clone https://github.com/grahamjonesgs/car_s.git
git clone -b ros2  https://github.com/allenh1/rplidar_ros.git
git clone -b jazzy https://github.com/CCNYRoboticsLab/imu_tools.git

cd ~/ros_ws
source /opt/ros/jazzy/setup.bash
rosdep install -i --from-paths src --rosdistro jazzy -y
MAKEFLAGS=-j2 colcon build --symlink-install --parallel-workers 2
```

The limited parallelism stops the Pi running out of memory; the first build
takes a while. `rplidar_ros` and `imu_tools` are built from source rather than
installed from apt.

Add these to the end of `~/.bashrc`:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros_ws/install/setup.bash
```

### Updating

```bash
cd ~/ros_ws/src
git -C car_s pull
git -C rplidar_ros pull --ff-only
git -C imu_tools pull --ff-only
cd ~/ros_ws && MAKEFLAGS=-j2 colcon build --symlink-install --parallel-workers 2
```

After an `apt upgrade` that updates ROS packages, rebuild the workspace.

## Setting up the remote control machine

Install ROS 2 Jazzy (`ros-jazzy-desktop` if you want RViz), then build
`car_s` there too. Without pigpio installed, only `key_cmd` and
`imu_normalize` are built, which is all that's needed:

```bash
mkdir -p ~/ros_ws/src && cd ~/ros_ws/src
git clone https://github.com/grahamjonesgs/car_s.git
cd ~/ros_ws
source /opt/ros/jazzy/setup.bash
rosdep install -i --from-paths src --rosdistro jazzy -y
colcon build --symlink-install --packages-select car_s
source install/setup.bash
```

Both machines must be on the same network and use the same `ROS_DOMAIN_ID`
(neither sets one by default, so both use 0). If you set one, put
`export ROS_DOMAIN_ID=<n>` in `~/.bashrc` on both. Check the link from the
remote machine with `ros2 topic list` while the car is running.

## Running the car

### On the Pi

Full robot: motors, IMU, magnetometer, lidar and `robot_state_publisher`:

```bash
ros2 launch car_s robot_car.launch.py
```

Without the lidar:

```bash
ros2 launch car_s car_s_launch.yaml
```

Optional, to fuse the IMU (and magnetometer) into an orientation estimate on
`imu/data`:

```bash
ros2 run imu_filter_madgwick imu_filter_madgwick_node --ros-args \
  -p use_mag:=false -p publish_tf:=false
```

`publish_tf:=false` is required. Otherwise the filter publishes its own
`odom` → `imu_link` transform, which clashes with the URDF. Leave `use_mag`
off until the magnetometer has been calibrated.

### On the remote machine

```bash
ros2 run car_s key_cmd
```

Press `m` first to enable the motors. Lift the wheels off the ground the first
time after any change.

| Key | Action |
|---|---|
| `m` | Motors on / off |
| ↑ / ↓ | Forward / backward |
| ← / → | Turn on the spot anticlockwise / clockwise |
| `8` / `9` | Drive forward turning left / right |
| Space | Stop |
| `f` / `s` | Speed up / slow down by 0.1 m/s (`f` also drives forward). Starts at 0.2 m/s |
| `z` / `x` | Acceleration ramp up / down by 0.1 m/s² |
| `v` / `c` | Acceleration ramp to 1.0 / off |
| `0`–`5` | Microsteps 1, 2, 4, 8, 16, 32 |
| Ctrl-C | Quit |

In the default auto mode the car stops 0.1 s after the last command and
`key_cmd` sends one command per key press, so **hold the key down** to keep
moving. To keep moving after a single press, switch to continuous mode:

```bash
ros2 topic pub --once /motor_mode std_msgs/msg/Int32 "{data: 1}"
```

Other useful commands:

```bash
ros2 topic pub --once /motor_on std_msgs/msg/Bool "{data: true}"
ros2 topic pub --once /motor_accel std_msgs/msg/Float32 "{data: 0.5}"
ros2 topic echo /odom --field pose.pose.position
ros2 topic echo /imu/data_raw
ros2 topic hz /scan
```

To view the car in RViz on the remote machine, set the fixed frame to `odom`
and add TF, LaserScan (`/scan`) and RobotModel (topic `/robot_description`).

## IMU calibration

The gyro and accelerometer offsets are hard-coded as `NGx`…`NAz` near the top
of [src/pi_car_imu.cpp](src/pi_car_imu.cpp) and added to every reading.

1. Put the car on a level surface and keep it still.
2. Run `car_imu` and `ros2 run car_s imu_normalize`, and wait for the averages
   to settle (a few thousand readings).
3. The averages should be 0 for all gyro axes and accel X/Y, and 9.81 for
   accel Z. For each value, adjust the offset by the error: for example if
   gyro X averages 0.02, subtract 0.02 from `NGx`; if accel Z averages 9.75,
   add 0.06 to `NAz`.
4. Rebuild and repeat until the averages are close.

## Troubleshooting

| Problem | Fix |
|---|---|
| `gpio init failed` | `pigpiod` isn't running: `sudo systemctl start pigpiod`, check with `pigs hwver` |
| Motors don't move | Send `motor_on` true (`m` in `key_cmd`). In auto mode, hold the key down |
| Lidar node fails to open `/dev/ttyUSB0` | Check the lidar appears in `lsusb` and `ls /dev/ttyUSB*`. Check you're in `dialout` with `groups` |
| `Failed to open I2C device` | Check the wiring, and that `dtparam=i2c_arm=on` is set |
| Remote machine can't see topics | Same network and `ROS_DOMAIN_ID` on both, check `ros2 topic list` on each |
| Car turns the wrong way | Check the DIR wiring. With up-arrow the car should drive forward; with left-arrow it should turn anticlockwise seen from above |
| Build killed on the Pi | Out of memory, use the `MAKEFLAGS=-j2 ... --parallel-workers 2` build command |
